# ODYSSEY STM32MP157C Buildroot Build Flow

## 1. Purpose

This document describes the practical Buildroot build and maintenance flow used for the **Seeed Studio Odyssey STM32MP157C** platform in this project.

It is intended to answer the questions that usually appear after the initial bring-up work is complete:

- where persistent changes should live
- what each Buildroot output directory means
- which command to use after each type of change
- when a full kernel rebuild is required
- how to verify that the generated image really contains the intended kernel, DTB, rootfs, and image-layout changes
- how to avoid common WSL / Buildroot mistakes

The current validated baseline is:

```text
Buildroot: 2026.05.1
Kernel:    Linux 6.6
Board:     Seeed Studio Odyssey STM32MP157C
DTS:       st/stm32mp157c-odyssey
Host:      WSL Ubuntu
```

---

## 2. Source-of-Truth Rule

The most important Buildroot maintenance rule for this project is:

> **Never treat `output/build` or `output/target` as the source of truth. Persistent project changes must live in Buildroot configuration, board files, overlays, or patches.**

The intended flow is:

```text
Persistent source files
        |
        v
Buildroot configuration
        |
        v
board/seeed/stm32mp157c-odyssey/
        |
        +-- linux.config
        +-- patches/linux/
        +-- overlay/
        +-- genimage.cfg
        |
        v
make
        |
        +-- output/build/
        +-- output/target/
        +-- output/host/
        +-- output/images/
        |
        v
sdcard.img
        |
        v
flash SD card
        |
        v
runtime verification
```

Changes made directly under `output/build` or `output/target` are useful for temporary experiments only and may disappear after a clean rebuild.

## 3. Important Project Paths

### 3.1 Board configuration

```text
board/seeed/stm32mp157c-odyssey/
```

This directory should contain the persistent board-specific implementation.

Important files currently include:

```text
board/seeed/stm32mp157c-odyssey/linux.config
board/seeed/stm32mp157c-odyssey/genimage.cfg
board/seeed/stm32mp157c-odyssey/patches/linux/
board/seeed/stm32mp157c-odyssey/overlay/
```

### 3.2 Kernel configuration

```text
board/seeed/stm32mp157c-odyssey/linux.config
```

This is the persistent board kernel configuration source.

The generated kernel configuration is:

```text
output/build/linux-6.6/.config
```

Use the generated `.config` to verify the result, but do not treat it as the persistent source.

### 3.3 Linux patches

```text
board/seeed/stm32mp157c-odyssey/patches/linux/
```

Board-specific Linux source changes should be stored here as patches.

Example:

```text
9999-odyssey-enable-fs-usb-device.patch
```

### 3.4 Root filesystem overlay

```text
board/seeed/stm32mp157c-odyssey/overlay/
```

Files placed here are copied into the final root filesystem.

Examples:

```text
overlay/etc/init.d/S50usb-acm
overlay/etc/inittab
overlay/boot/extlinux/extlinux.conf
```

### 3.5 Image layout

```text
board/seeed/stm32mp157c-odyssey/genimage.cfg
```

This controls the final SD-card image partition layout, including the added FAT `DEVBOOT` partition.

## 4. Buildroot Output Directories

Understanding the `output/` tree prevents many debugging mistakes.

### `output/build/`

Contains unpacked and patched package source trees.

Examples:

```text
output/build/linux-6.6/
output/build/uboot-*/
```

Use this directory for:

- inspecting the exact source Buildroot is compiling
- confirming whether patches were applied
- temporary experiments

Do not use it as persistent source storage.

### `output/target/`

Contains the assembled target root filesystem before final filesystem/image generation.

Use it to verify that overlay files were copied correctly.

Examples:

```text
output/target/etc/init.d/S50usb-acm
output/target/etc/inittab
output/target/boot/extlinux/extlinux.conf
```

Do not edit it as the permanent source.

### `output/host/`

Contains Buildroot host tools and cross-toolchain components.

Examples:

```text
output/host/bin/dtc
output/host/bin/arm-buildroot-linux-gnueabihf-gcc
```

This directory is useful for image/DTB inspection and for tools generated by Buildroot itself.

### `output/images/`

Contains final deployable artifacts.

Important outputs include:

```text
output/images/sdcard.img
output/images/zImage
output/images/stm32mp157c-odyssey.dtb
output/images/rootfs.ext2
output/images/rootfs.ext4
```

The file normally flashed to the SD card is:

```text
output/images/sdcard.img
```

## 5. WSL Environment

Buildroot is currently built under WSL Ubuntu.

### 5.1 Recommended PATH

Use a clean Linux PATH:

```bash
export PATH=/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin
```

The permanent WSL setting used during bring-up is:

```ini
[interop]
appendWindowsPath=false
```

in:

```text
/etc/wsl.conf
```

After changing `/etc/wsl.conf`, restart WSL from Windows:

```powershell
wsl --shutdown
```

### 5.2 Shell discipline

Run Buildroot commands inside the WSL Bash shell.

Do not paste Bash commands directly into Windows PowerShell.

During interactive bring-up, avoid wrapping command sequences with:

```bash
set -e
```

or:

```bash
set -euo pipefail
```

because a single diagnostic command returning non-zero can terminate the shell/script and obscure the actual problem.

### 5.3 Parallel build level

Use:

```bash
make -j8
```

rather than:

```bash
make -j$(nproc)
```

The fixed value is intentional to reduce WSL memory/resource pressure and improve repeatability.

## 6. Baseline Build

From the Buildroot root directory:

```bash
cd ~/github/buildroot-2026.05.1

export PATH=/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin

make stm32mp157c_odyssey_defconfig
make -j8
```

For the current project state, the configured kernel baseline is Linux 6.6 rather than the original 5.10.1 baseline.

Relevant Buildroot configuration includes:

```text
BR2_PACKAGE_HOST_LINUX_HEADERS_CUSTOM_6_6=y
BR2_LINUX_KERNEL_CUSTOM_VERSION_VALUE="6.6"
BR2_LINUX_KERNEL_INTREE_DTS_NAME="st/stm32mp157c-odyssey"
```

After a configuration edit, use:

```bash
make olddefconfig
```

to normalize the Buildroot configuration before rebuilding.

## 7. Rebuild Decision Table

Use this table as the normal first reference after making a change.

| Change type | Persistent source | Recommended action |
|---|---|---|
| Rootfs overlay file | `board/.../overlay/` | `make -j8` |
| `extlinux.conf` | `board/.../overlay/boot/extlinux/extlinux.conf` | `make -j8` |
| `/etc/inittab` | `board/.../overlay/etc/inittab` | `make -j8` |
| init script | `board/.../overlay/etc/init.d/` | `make -j8` |
| `genimage.cfg` | `board/.../genimage.cfg` | `make -j8` |
| Buildroot `.config` | top-level `.config` | `make olddefconfig && make -j8` |
| kernel config source | `board/.../linux.config` | `make linux-dirclean && make -j8` |
| Linux source patch | `board/.../patches/linux/*.patch` | `make linux-dirclean && make linux-patch && make -j8` |
| kernel version | Buildroot `.config` | `make linux-dirclean && make -j8` |
| DTS patch | `board/.../patches/linux/*.patch` | `make linux-dirclean && make linux-patch && make -j8` |

The more targeted commands below are useful when diagnosing a specific layer.

## 8. Linux Package Build Flow

### 8.1 `make linux-dirclean`

Use this when the Linux source tree must be recreated from scratch.

It removes the unpacked kernel build directory so Buildroot will:

1. unpack Linux again
2. apply patches again
3. regenerate configuration
4. rebuild the kernel and DTBs

Typical use cases:

- changed Linux patch files
- changed kernel version
- patch state became unclear
- temporary edits were made directly under `output/build/linux-*`

Command:

```bash
make linux-dirclean
```

### 8.2 `make linux-patch`

Use this to stop after unpacking and applying Linux patches.

```bash
make linux-patch
```

This is particularly useful for validating a new patch before performing the full kernel build.

Example verification:

```bash
grep -A15 '^&usbotg_hs' \
output/build/linux-6.6/arch/arm/boot/dts/st/stm32mp157c-odyssey.dts
```

### 8.3 `make linux-configure`

Use this to generate/configure the Linux tree without doing the complete final image build.

```bash
make linux-configure
```

Then inspect:

```bash
output/build/linux-6.6/.config
```

Example:

```bash
grep -E \
'CONFIG_USB_DWC2_PERIPHERAL=|CONFIG_USB_GADGET=|CONFIG_USB_CONFIGFS=|CONFIG_USB_CONFIGFS_ACM=|CONFIG_PHY_STM32_USBPHYC=' \
output/build/linux-6.6/.config
```

### 8.4 Full Linux rebuild

After patch/config verification:

```bash
make -j8
```

This regenerates the final kernel, DTB, rootfs, and SD-card image as needed.

## 9. Root Filesystem Overlay Flow

For rootfs files, always modify the board overlay.

Example:

```text
board/seeed/stm32mp157c-odyssey/overlay/etc/init.d/S50usb-acm
```

After editing:

```bash
make -j8
```

Verify the assembled target tree:

```bash
ls -l output/target/etc/init.d/S50usb-acm
```

For `inittab`:

```bash
grep ttyGS0 output/target/etc/inittab
```

For extlinux:

```bash
grep -n 'append' output/target/boot/extlinux/extlinux.conf
```

The target tree should reflect the overlay before the final filesystem/image is trusted.

---

## 10. `genimage.cfg` / SD-card Image Flow

Changes to:

```text
board/seeed/stm32mp157c-odyssey/genimage.cfg
```

control the final SD-card partition layout.

A normal rebuild is:

```bash
make -j8
```

Verify the final image with:

```bash
fdisk -l output/images/sdcard.img
```

and:

```bash
sgdisk -p output/images/sdcard.img
```

Current expected GPT names are:

```text
fsbl1
fsbl2
ssbl
rootfs
devboot
```

The `DEVBOOT` partition is currently a convenience FAT partition, while U-Boot still loads the kernel and DTB from `/boot` on the `rootfs` partition.

---

## 11. DTB Verification Flow

Do not assume that a DTS patch means the flashed DTB contains the desired properties.

Always verify the final generated binary DTB when changing hardware description.

Example:

```bash
output/host/bin/dtc \
-I dtb -O dts \
output/images/stm32mp157c-odyssey.dtb \
2>/dev/null |
grep -A22 'usb-otg@49000000'
```

For USBPHYC:

```bash
output/host/bin/dtc \
-I dtb -O dts \
output/images/stm32mp157c-odyssey.dtb \
2>/dev/null |
grep -A18 'usbphyc@5a006000'
```

This verifies the **final artifact**, not just the intermediate source tree.

---

## 12. Boot Artifact Verification

Before flashing, useful checks include:

```bash
ls -lh output/images/zImage
ls -lh output/images/stm32mp157c-odyssey.dtb
ls -lh output/images/sdcard.img
```

After boot, verify the running kernel version:

```bash
uname -a
```

For the current baseline, the expected kernel family is:

```text
Linux 6.6
```

The boot log should also show:

```text
Linux version 6.6.0 ...
```

This prevents accidentally testing an old image after a successful build.

---

## 13. Root Filesystem Boot Verification

The project uses a stable GPT partition label rather than a hardcoded block-device name.

Current `extlinux.conf` boot argument:

```text
append root=PARTLABEL=rootfs rootwait
```

This avoids depending on whether Linux enumerates the SD card as:

```text
mmcblk0
```

or:

```text
mmcblk1
```

A healthy boot sequence includes:

```text
Kernel command line: root=PARTLABEL=rootfs rootwait
Waiting for root device PARTLABEL=rootfs...
EXT4-fs (...p4): mounted ...
VFS: Mounted root ...
```

## 14. Recommended Full Rebuild Sequence After Linux Patch Changes

For a Linux/DTS patch change, the preferred reproducible flow is:

```bash
cd ~/github/buildroot-2026.05.1

export PATH=/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin

make linux-dirclean
make linux-patch

# Inspect patched source here.

make linux-configure

# Inspect output/build/linux-6.6/.config here.

make -j8
```

Then verify:

```bash
output/host/bin/dtc \
-I dtb -O dts \
output/images/stm32mp157c-odyssey.dtb \
2>/dev/null | less
```

and inspect the final image:

```bash
sgdisk -p output/images/sdcard.img
```

This sequence is slower than blindly running `make`, but it is much easier to audit during hardware bring-up.

## 15. Recommended Fast Flow for Overlay-only Changes

For changes limited to files under:

```text
board/seeed/stm32mp157c-odyssey/overlay/
```

normally use:

```bash
make -j8
```

Then verify the copied file under:

```text
output/target/
```

before flashing the image.

Examples:

```bash
grep ttyGS0 output/target/etc/inittab
cat output/target/boot/extlinux/extlinux.conf
```

## 16. Recommended Fast Flow for Image-layout Changes

For `genimage.cfg` changes:

```bash
make -j8
```

Then verify:

```bash
fdisk -l output/images/sdcard.img
sgdisk -p output/images/sdcard.img
```

If a FAT image is generated, inspect it directly when useful:

```bash
mdir -i output/images/devboot.vfat ::
```

Expected DEVBOOT contents include:

```text
zImage
stm32mp157c-odyssey.dtb
```

## 17. Common Failure Modes

### 17.1 Patch changed but old kernel tree was reused

Symptom:

- patch file looks correct
- generated kernel behaves as before

Action:

```bash
make linux-dirclean
make linux-patch
```

Then inspect the patched source before rebuilding.

### 17.2 Edited `output/build` directly

Symptom:

- fix works once
- disappears after rebuild/clean

Action:

Move the change into:

```text
board/.../patches/linux/
```

or the appropriate persistent board file.

### 17.3 Edited `output/target` directly

Symptom:

- rootfs modification disappears later

Action:

Move the file into:

```text
board/.../overlay/
```

### 17.4 Built successfully but flashed an old image

Verify before flashing:

```bash
ls -lh --time-style=long-iso output/images/sdcard.img
```

After boot, verify the kernel version and relevant runtime logs.

### 17.5 SD/eMMC numbering changed

Do not use:

```text
root=/dev/mmcblk0p4
```

Keep:

```text
root=PARTLABEL=rootfs rootwait
```

### 17.6 WSL command unexpectedly exits

Avoid `set -e` while interactively diagnosing Buildroot failures.

Run commands individually so the first failing step remains visible.

## 18. Current Build Flow Summary

The normal development flow is:

```text
1. Modify persistent source
       |
       +-- Buildroot config
       +-- linux.config
       +-- patches/linux/
       +-- overlay/
       +-- genimage.cfg
       |
2. Choose rebuild depth
       |
       +-- overlay/genimage -> make -j8
       +-- kernel patch/config -> linux-dirclean / patch / configure
       |
3. Build
       |
       +-- make -j8
       |
4. Verify intermediates
       |
       +-- output/build
       +-- output/target
       |
5. Verify final artifacts
       |
       +-- output/images/zImage
       +-- output/images/*.dtb
       +-- output/images/sdcard.img
       |
6. Flash SD card
       |
7. Verify runtime
       |
       +-- boot log
       +-- uname -a
       +-- device-specific functional checks
```

---

## 19. Current Policy

For this project:

```text
Persistent source       = Buildroot board/config files
output/build            = intermediate patched source
output/target           = assembled rootfs staging tree
output/host             = Buildroot host tools/toolchain
output/images           = deployable artifacts
sdcard.img              = flash target
```

The project should favor **reproducible board-local changes** over one-off edits inside Buildroot output directories.
